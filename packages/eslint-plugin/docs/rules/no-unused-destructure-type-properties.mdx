When a destructuring pattern is annotated with an inline type, nothing else refers to that type.
Any property the type declares but the pattern does not destructure is required from callers without being read through the pattern.
This often happens when a property is removed from the pattern but left behind in its type, such as when refactoring a UI component's props.

This rule reports properties, index signatures, tuple elements, and `Record` keys of inline types that are not used by the destructuring pattern they annotate.
It checks function parameters and variable declarations, including nested inline types.
Signatures without an implementation, such as overload signatures, function types, and anything in a `declare` block or `.d.ts` file, are not checked.

## Examples

<Tabs>
<TabItem value="❌ Incorrect">

```ts
function Button({ text }: { text: string; onClick: () => void }) {
  return text;
}

function getFirst([first]: [string, number]) {
  return first;
}

function getName({ name }: Record<'id' | 'name', string>) {
  return name;
}

function getCity({
  address: { city },
}: {
  address: { city: string; street: string };
}) {
  return city;
}
```

</TabItem>
<TabItem value="✅ Correct">

```ts
function Button({ text, onClick }: { text: string; onClick: () => void }) {
  return [text, onClick];
}

function getFirst([first]: [string]) {
  return first;
}

function getName({ name }: Record<'name', string>) {
  return name;
}

function getCity({ address: { city } }: { address: { city: string } }) {
  return city;
}
```

</TabItem>
</Tabs>

### Named Types

Type aliases, interfaces, and other type references might be used elsewhere, so this rule does not report on their properties.
Only types written inline in the annotation are checked.

```ts
interface ButtonProps {
  text: string;
  onClick: () => void;
}

// ✅ Not reported: ButtonProps might be used elsewhere
function Button({ text }: ButtonProps) {
  return text;
}
```

### Rest Elements and Skipped Elements

A rest element collects every remaining property, so patterns containing one are not reported.
Tuple elements that are explicitly skipped before a later element are considered used.

```ts
function Button({ text, ...rest }: { text: string; onClick: () => void }) {
  return [text, rest];
}

function getSecond([, second]: [string, number]) {
  return second;
}
```

## When Not To Use It

Removing an unused property makes a parameter's type less specific.
If you intentionally declare properties you don't read, such as to require callers to provide them ahead of a planned change, this rule might not be for you.
You might consider using [ESLint disable comments](https://eslint.org/docs/latest/use/configure/rules#using-configuration-comments-1) for those specific situations instead of completely disabling this rule.
