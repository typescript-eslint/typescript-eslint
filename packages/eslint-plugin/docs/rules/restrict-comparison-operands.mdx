TypeScript allows any two objects to be compared with the relational operators `<`, `>`, `<=` and `>=`.
JavaScript compares objects by [converting them to primitives](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Less_than#description) first, using their `[Symbol.toPrimitive]()` or `valueOf()` method.
Objects that do not override either of them, such as plain objects, arrays, `Map`s and functions, are converted to their string form instead, for example `"[object Object]"` or `"1,2,3"`.
Comparing them with another object compares those strings, and comparing them with a number compares against `NaN`, so the result has nothing to do with the values being compared.

This rule reports operands of relational comparisons whose type is an object that does not convert to a primitive value.
Objects that define `[Symbol.toPrimitive]()` or `valueOf()`, such as `Date` and `Number`, can be compared.
Types that may also hold primitives, such as `{}`, `Object` and `object`, are not reported.

## Examples

<Tabs>
<TabItem value="❌ Incorrect">

```ts
declare const a: { value: number };
declare const b: { value: number };
a < b;

declare const versions: number[];
versions >= 2;

class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}
declare const point: Point;
point > 0;
```

</TabItem>
<TabItem value="✅ Correct">

```ts
declare const a: { value: number };
declare const b: { value: number };
a.value < b.value;

declare const start: Date;
declare const end: Date;
start < end;

class Money {
  constructor(private cents: number) {}

  valueOf(): number {
    return this.cents;
  }
}
declare const price: Money;
declare const budget: Money;
price <= budget;
```

</TabItem>
</Tabs>

## When Not To Use It

If your codebase intentionally compares objects by their string form, such as instances of a class that only defines `toString()`, you may want to disable this rule or convert the values to strings explicitly with `String()` before comparing them.
