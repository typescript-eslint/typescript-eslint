Explicit return type annotations can retain union constituents after the implementation no longer requires them.
Callers must then handle types that TypeScript does not infer for any returned expression.

This rule reports a union constituent written in a return type when the function would still type-check without it:
no returned expression is assignable to that constituent, and every returned expression is assignable to another one.
Literal types satisfy their corresponding primitive types, so returning `'ready'` satisfies a `string` constituent.
A function body that can end without returning a value requires `undefined` or `void`.

The rule checks unions written directly as the return type, and unions written inside it as:

- the type argument of the `Promise` that an async function returns
- an array or tuple element type
- a property type of an object type
- a type argument of a class or an interface, such as `Promise`, `Set`, or `Map`

<TabItem value="❌ Incorrect">

```ts
function getStatus(): string | null {

}

async function getAsyncStatus(): Promise<string | null> {
  return 'ready';
}

function getStatuses(): (string | null)[] {
  return ['ready'];
}

function getUser(): { name: string | null } {
  return { name: 'user' };
}
```

```ts
function getStatus(): string {
  return 'ready';
}

async function getAsyncStatus(): Promise<string> {
  return 'ready';
}

function getStatuses(): string[] {
  return ['ready'];
}

function getUser(): { name: string } {
  return { name: 'user' };
}
```

## Limitations

This rule only inspects unions written in the return type annotation.
It does not expand type aliases, and it does not inspect the type arguments of a type alias.
It also does not inspect function types, optional properties, or optional and rest tuple elements.

A type argument of a class or an interface is compared with the returned values that are instances of that class or interface, or of one that extends it.
For `Array`, `ReadonlyArray`, and `ArrayLike`, returned arrays and tuples are compared as well, and for `PromiseLike`, returned promises.
Other returned values, such as an object literal returned for a generic interface, are not compared.

The rule does not report when a returned expression is `any` or `unknown`.
It also does not report when TypeScript infers the type of a returned expression from the return type, as it does for `[]` or `new Set()`.

To avoid reporting on return types that may describe an external contract, the rule skips overload implementations, contextually typed functions and object methods, inherited or implemented class methods and function-valued fields, decorated members, and members in decorated classes.
It also skips generators.

The rule follows the types produced by TypeScript's type checker rather than performing separate runtime reachability analysis.
Compiler options therefore affect its results.
When `noUncheckedIndexedAccess` is disabled, an indexed access can exclude `undefined` from its inferred type even though it may produce `undefined` at runtime.
When `strictNullChecks` is disabled, `null` and `undefined` constituents are not reported.

## When Not To Use It

An API may intentionally declare values that its current implementation does not return, such as for forward compatibility.
A function may also return a new array or object that its callers later fill with other values.
If those conventions are common in your project, you might not want to use this rule.
