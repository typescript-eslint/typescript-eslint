TypeScript's type system is structural, so a class's name can be used as a type for any value with the same shape.
That includes object literals that were never passed through the class's constructor.

Constructors are often relied on to validate inputs or set up internal state.
An object literal that skips the constructor also skips those guarantees, and won't pass `instanceof` checks for the class.
This rule reports values that are not instances of a class used where one is expected: in assignments, arguments, return values, type assertions, and so on.
That includes object literals as well as other values whose types are only structurally compatible with the class, such as a `Promise<{ x: number; y: number }>` assigned to a `Promise<Point>`.

## Examples

<Tabs>
<TabItem value="❌ Incorrect">

```ts
class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}

const point: Point = { x: -1, y: -2 };

declare const plain: { x: number; y: number };
const points: Point[] = [plain];
```

</TabItem>
<TabItem value="✅ Correct">

```ts
class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}

const point = new Point(1, 2);

const points: Point[] = [new Point(1, 2)];
```

</TabItem>
</Tabs>

## When Not To Use It

If you intentionally use classes as structural types, such as for lightweight data containers that don't rely on constructor logic, you might prefer to declare those shapes as interfaces or type aliases instead.
If your project intentionally relies on that pattern, this rule may not be for you.
